# Legacy Model

This directory contains the original research code for the paper *"Energy and Climate Policy Implications on the Deployment of Low-Carbon Ammonia Technologies"* (Chyong, Italiani, Kazantzis). It is a stochastic discounted cash flow (DCF) model that evaluates four ammonia production technologies under IRA tax credits.

---

## Technologies

| Code | Technology | Description |
|---|---|---|
| AP SMR | Steam Methane Reforming | Baseline, grid-connected |
| AP CCS | SMR with Carbon Capture | 95.6% CO₂ capture rate |
| AP BH2S | Biomass + SMR (Blue H₂) | Biomass gasification-fed SMR |
| AP AEC | Alkaline Electrolysis Cell | Green hydrogen, electricity-driven |

## Business Model Scenarios

| Scenario | Electricity Source | AP SMR included |
|---|---|---|
| A | US grid electricity (EIA AEO 2023 CO₂ intensity) | Yes |
| B | Build & own a wind/battery hybrid farm (CAPEX-intensive) | No |
| C | Power Purchase Agreement with wind/battery farm (OPEX-intensive, priced at farm LCOE) | No |

Simulations run for both **2023** and **2030** start years. Matching constraints (yearly, monthly, hourly) govern how the renewable generation must align with plant demand in scenarios B and C.

IRA tax credits modeled: **45V, 45Q, 45Y, 48C, 48E**.

## Configuration

**Before running anything**, open `optimization.py` and update:

```python
ROOT_DIR = r'C:/path/to/your/legacy/directory/'  # must end with /
```

This `ROOT_DIR` is imported by all other scripts via `cleaning_optimization_data.py` and `_path_dependent_data_handling.py`. Every data file path is built from it.

## Running the Model

All scripts are run from inside the `legacy/` directory. The working directory must be `legacy/` because imports are relative.

```bash
cd legacy
```

### Step 1 — (Optional) Re-run the optimization

Skip this step if you are using the pre-computed `power_markets/solar_optimization_results.xlsx`. Re-run only if you want to change location data or capacity factor assumptions.

```bash
python optimization.py
```

This calls the renewables.ninja API to retrieve hourly capacity factors for each US location and solves a linear program (PuLP) to minimize wind + battery + solar CAPEX subject to constant output. Results are written to `power_markets/solar_optimization_results.xlsx`.

### Step 2 — (Optional) Re-run the PPA LCOE model

Skip this step if you are using the pre-computed `data/PPA_output.xlsx`. Re-run only if wind/battery capacities or financial inputs changed.

```bash
python PPA_model_testing.py
```

This solves for the LCOE (via root-finding) that sets NPV = 0 for a standalone wind/battery/solar farm under scenarios C and D. Output is written to the path defined by `PPA_OUTPUT_FILE_NAME` inside that script.

### Step 3 — Run the probabilistic model

This is the main step that produces all paper results.

```bash
python probabilistic_model_runner.py
```

Open the file first and configure the three variables at the bottom:

```python
CBAM = False        # True to enable Carbon Border Adjustment Mechanism
matching = 'monthly'  # 'hourly', 'monthly', or 'yearly'
mult = 40           # multiplier: total simulations = 100 * mult (4,000 recommended)
```

Uncomment the lines for the metrics you want to compute. By default only `NPV` is active:

```python
NPV_dataset   = run_simulation(100*mult, NPV=True,   ...)
# CAC_dataset = run_simulation(100*mult, CAC=True,   ...)
# CI_dataset  = run_simulation(100*mult, CI=True,    ...)
# TC_dataset  = run_simulation(100*mult, Potential_TC=True, ...)
# ...
```

Results are written to an Excel file named `v14_DATASET_{matching}.xlsx` (or `v14_DATASET_CBAM_{matching}.xlsx`). Each metric is written to a separate sheet.

**Available metrics:**

| Flag | Description | Output columns |
|---|---|---|
| `NPV=True` | Net Present Value (with IRA credits) | `AP_SMR_NPV`, `AP_CCS_NPV`, `AP_BH2S_NPV`, `AP_AEC_NPV` |
| `NP_NPV=True` | NPV without IRA credits | same structure |
| `CAC=True` | Carbon Abatement Cost ($/tCO₂) | `AP_CCS_CAC`, `AP_BH2S_CAC`, `AP_AEC_CAC` |
| `CI=True` | Carbon Intensity over time (2023–2050) | per-year columns per technology |
| `Potential_TC=True` | Total tax credit support ($B) | 45V/45Q/45Y/48E per technology |
| `absolute_support=True` | Tax credits broken out by credit type | per-credit-type columns |
| `CAPEX_OPEX=True` | CAPEX and monthly OPEX profiles | arrays per technology |
| `ROI=True` | Return on Investment | same structure as NPV |
| `El_market=True` | Grid electricity market price (scenarios A/B only) | `Grid Electricity` |
| `Sensitivity=True` | Sensitivity analysis inputs per technology | CAPEX, elec cost, OPEX, feedstock, NH3 price, CI, etc. |
| `quality_assurance=True` | Full cash flow breakdown per simulation | writes per-simulation Excel files to `quality_assurance/` |

Each row in the output DataFrame represents one simulation for one (time, scenario) combination.

### Step 4 — Run the deterministic model

```bash
python deterministic_model_runner.py
```

This uses mean values for all probabilistic inputs (via `average_values_from_JSON_inputs`). Useful for LCOA (levelized cost of ammonia) and sensitivity bar charts. Configuration is the same as the probabilistic runner.

### Step 5 — Generate figures

Run individual scripts from `visualization/`. Each script reads one or more of the output Excel files and produces paper figures. Edit the file path variables at the top of each script to point to your output files.

```bash
python visualization/FIGURE_npv_cac_ci.py
python visualization/FIGURE_sensitivity.py
python visualization/FIGURE_total_support.py
# etc.
```

## Key Model Parameters

All stochastic inputs are defined in `input_parameters.json` as uniform distributions `[low, high]`. The deterministic model uses their midpoints.

| Parameter | Stochastic Range | Source |
|---|---|---|
| CAPEX heuristics (I&C, piping, electrical, etc.) | Uniform per Peters et al. (2003) | SI Table S3 |
| AEC stack CAPEX (2023) | $750–$1,000/kWe | Bohm et al., Schmidt et al. |
| AEC stack CAPEX (2030) | $500–$1,000/kWe | IRENA 2020 |
| AEC efficiency η | 70%–78% (LHV) | Brauns et al. |
| Biomass price | $50.68–$118.25/tonne | Literature |
| Natural gas upstream emissions | 0.01–7.9 g CO₂/kWh_e | Literature |
| AP SMR direct emissions | 0.243–0.527 kg CO₂/kg H₂ | Calculated |
| Battery fixed O&M | $6.16–$49.33/kW-year | Cole et al. |
| Battery variable O&M | $0–$8.63/MWh | Cole et al. |
| Battery lifetime | 13–20 years | Cole et al. |
| 48E tax credit | 30%–40% of farm CAPEX | IRA 2022 |
| EU CO₂ price (CBAM) | $35–$100/tCO₂e | McDonald et al. |

Plant scale: **2,717 TPD NH₃** (99.9% N₂ conversion, Linde Ammonia Concept). Construction time: 36 months. Operating lifetime: 480 months (40 years). Availability factor: 90%.

Market prices (natural gas, ammonia) follow correlated GBM (correlation = 0.8). Electricity prices follow independent GBM. Price paths are seeded per simulation for reproducibility.

## Known Issues

1. **Hardcoded `ROOT_DIR`** — `optimization.py` line 16 contains `C:/Users/eduar/...`. Update this before running.

2. **Exposed API keys** — `optimization.py` lines 18–20 contain three renewables.ninja API keys. Replace with your own and do not commit the file with real keys.

3. **Four runner scripts** — `probabilistic_model_runner.py`, `deterministic_model_runner.py`, `deterministic_model_runner_v2.py`, and `probabilistic_model_runner_QA.py` contain significant code duplication. `probabilistic_model_runner.py` is the canonical one for paper results.

4. **QA runner typo bug** — `probabilistic_model_runner_QA.py` contains a known bug in variable naming. Use `quality_assurance=True` in the main probabilistic runner instead.

5. **Wildcard imports** — most files use `from module import *`, which can cause namespace collisions if module load order changes.

6. **No `requirements.txt`** — dependencies must be installed manually (see Prerequisites).

7. **`PPA_OUTPUT_FILE_NAME` coupling** — `probabilistic_model_runner.py` imports this constant from `PPA_model_testing.py` and reads the corresponding Excel file. If you rename the PPA output file, update both scripts.
